# GC4653首次初始化测试

阶段链接：[[../05-GC4653视觉链路|05 GC4653视觉链路]] · 连接：USB NCM SSH `root@10.128.80.1` · 工作目录：`/root/uav/samples`

## 操作

```sh
cd /root/uav/samples
/mnt/system/usr/bin/sensor_test
```

## 关键输出

- MMF版本：`d4003f15b-musl_riscv64`
- 配置：`/mnt/data/sensor_cfg.ini`
- 传感器：`GCORE_GC4653_MIPI_4M_30FPS_10BIT`
- I2C：bus 4，地址29（程序输出原值）
- MIPI device：0
- Lane ID：`4, 3, 2, -1, -1`
- MCLK已启用，选择1
- 传感器模式：2560×1440、10 bit、Linear、WDR关闭
- 明确成功信息：`GC4653 1440P 30fps 10bit LINEAR Init OK!`
- ISP参数识别：sensor 4653，`gc4653 30fps`，创建时间2024-03-26
- ISP线程：`ISP Dev 0 running!`

程序进入交互菜单：

```text
1: dump vi raw frame
2: dump vi yuv frame
3: set chn flip/mirror
4: linear wdr switch
5: AE debug
6: sensor dump
7: sensor proc
255: exit
```

随后按 Ctrl+C，程序输出ISP缓冲区Free信息后退出。

## 判定

**相机初始化通过，图像数据尚未验收。** 当前证据证明配置解析、传感器控制、MIPI/VI和ISP初始化成功；尚未执行菜单1/2，因此没有RAW/YUV样帧，不能判断画面内容、颜色、曝光、坏帧或实际连续帧率。

日志一处显示 `25.000000`，而传感器名称和初始化成功行写30 fps；先记录为日志口径不一致，后续以连续采帧时间戳实测帧率，不直接认定已经达到30 fps。

Ctrl+C是人工中止，不是程序崩溃。日志出现 `ISP Vipipe(0) Free ...`，表明本次至少执行了释放路径；下一次仍优先正常输入 `255`退出。

## 下一步

### 交互菜单隐藏提示问题

第二次测试中，在菜单输入 `2` 后终端没有显示新提示，再输入 `255` 也没有退出。该程序选择YUV dump后还会依次读取两个参数：

1. VI通道号 `0~1`；
2. 抓取循环次数，`11111` 表示无限循环。

部分固件把这两条提示写入系统日志而不是当前SSH终端，因此程序并未卡死。此次输入的 `255` 很可能被程序当作通道号，随后继续等待循环次数。

### 下一次操作

1. 若当前进程仍在等待，按 `Ctrl+C` 结束；看到ISP Free信息后再重启程序。
2. 依次输入 `2`、`0`、`1`，每个数字后按一次回车：选择YUV、通道0、抓取1帧。
3. 程序重新显示主菜单后，再输入 `255` 正常退出。
4. `ls -lht /root/uav/samples` 查找新文件并记录名称、大小。
5. 若当前目录没有文件，执行 `find /root /mnt/data /tmp -type f \\( -name '*.yuv' -o -name '*.raw' \\) 2>/dev/null`。
6. SCP到Windows；以程序输出和 `/proc/cvitek/vi` 为准确认像素格式，再转换查看。

## YUV单帧测试进展

按顺序输入 `2`、`0`、`1` 后，程序正常返回主菜单，证明隐藏参数已经被正确读取，交互流程没有阻塞。当前终端没有打印保存路径或成功/失败统计，因此暂记为“抓帧命令已执行，文件待确认”。下一步正常输入 `255` 退出，再检查当前目录、其他常见目录以及系统日志。

### 抓帧结果

- 文件：`/root/uav/samples/sample_0.yuv`
- `ls -lh` 显示大小：约5.3 MiB
- 生成位置与运行 `sensor_test` 时的工作目录一致。
- 判定：**GC4653单帧YUV抓取成功。**
- `logread`：当前Buildroot镜像未提供该命令，不影响本次判定。
- 退出 `sensor_test` 后读取 `/proc/cvitek/vi` 只剩表头：属于VI资源已经释放后的正常现象。若要查看活动状态，需保持 `sensor_test` 运行，并从第二个SSH会话读取该文件。

2560×1440的8 bit YUV420单帧理论大小为 `2560 × 1440 × 1.5 = 5,529,600` 字节，与 `ls` 显示的约5.3 MiB相符。仍需用 `stat` 获取精确字节数，并确认NV21/NV12排列后再转换图像。

### 2026-09-24 PATH与多帧文件名现象

- 在安装FFmpeg之前已经打开的PowerShell窗口中直接执行 `ffmpeg`，出现 `CommandNotFoundException`。原因是旧进程没有重新读取用户PATH；关闭后新开PowerShell，或直接调用 `D:\软件\ffmpeg\bin\ffmpeg.exe` 即可。
- `sensor_test` 输入抓取循环数3后，目标目录只发现 `sample_0.yuv`。该工具可能在循环中复用/覆盖同一文件名，因此单个文件不能作为3个独立样帧的证据。
- 后续画质复测改为每次只抓1帧，退出后立即将 `sample_0.yuv` 重命名为带序号的文件，再重复3轮。
