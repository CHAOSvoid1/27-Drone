# 无桨控制链路测试总览

> [!goal] 本轮目标
> 验证 **GC4653 → LicheeRV Nano → MAVLink/UART → PX4 H743 AIO V2 → 四合一 ESC → 1404-4500KV 电机** 的各段链路，并验证 **MTF-02P → PX4**、**ELRS → PX4** 与 QGroundControl 监控。终点是无桨电机低速、短时响应；不作飞行性能结论。

## RM2027空中机器人前瞻规则基线

依据《RoboMaster 2027 高校系列赛规则变更前瞻手册（20260909）》2.1.2与2.1.2.1，当前预研必须覆盖：

- 运行方式为全自动，初始区域为机库放置区，允许多机通信，不允许安装发射机构。
- 空中机器人必须能够持续悬停至少10秒。
- 机体外必须安装全包围桨叶保护罩，桨叶和机体不得外露；桨叶使用柔性材料。
- 必须配套紧急停桨遥控器/接收机，并配备安全员。
- 重量与最大伸展尺寸满足`y=-0.001225x+0.3225`，`y∈[0.15,0.249] kg`。当目标重量为0.200 kg时，对应最大尺寸`x=100 mm`。
- 最大供电容量、最大工作电压、裁判系统等仍为待定项，正式设计必须随正式规则复核。

前瞻手册只公布部分变更，本文把它作为预研边界，不视为最终检录标准。

打开 [[控制链路测试流程.canvas|阶段流程画布]]；每阶段的通过证据写入对应笔记，原始记录可复制 [[测试记录模板]]。已有的 [[27赛季无人机系统架构.canvas|系统架构图]]可作部件关系总图；其中电机/电池候选是较早方案，本轮以 **45A AM32 + 1404-4500KV、无桨台架** 和本测试计划的供电门禁为准。

针对本机约100 mm、200 g以下的定位、传感器和动态避障候选，统一分析见[[第三方方案评估总览]]；细项见[[微分智飞资料评估与小型无人机]]、[[MicoVIO预告与传感器替代评估]]和[[OmniRisk动态避障评估]]。第三方结果均不属于本机实测证据。

## 台架固定条件

- **从第一阶段到结束都拆除全部桨叶**；四个电机与 AIO 固定在绝缘台架上，周围清空松散物。
- 断电后才改线；首次供电前用万用表测电源正负极、短路、5V/3.3V 端与地；有条件用限流电源或 smoke stopper。
- 电脑 USB 先验证飞控，再逐个增加外设；ESC/电机测试通常还需主电池供电。不要以 USB 连接成功推断 ESC 已供电。
- 留出能一动作切断主电源的方式，遥控器设置明确的停机/解除锁定动作；人在电机旋转平面外。每次只做短时、低输出测试。
- 保存 QGC 参数备份、飞控日志、串口日志、相机样帧及每次接线照片。遇到异常发热、异味、电压骤降、非预期电机转动立即断电，回到上一已通过阶段。

## 串口分配草案

下面是**45A 版官方串口映射基础上的草案**；接线时再与实物丝印逐一核对。端口服务不能冲突；修改 PX4 的 `*_CONFIG` 后通常需要重启，再核对速率与模式。

| 链路 | 拟用 AIO 端口 | 连接与配置要点 |
|---|---|---|
| QGC ↔ PX4 | USB-C | 台架调试优先有线连接 |
| MTF-02P → PX4 | UART4 / `TELEM2` | 5V 供电、共地、TX→RX；PX4 MAVLink 端口 115200；模块用 MAVLink PX4 或 AUTO，按消息验证 |
| LicheeRV Nano → PX4 | UART1 / `TELEM1` | 3.3V LVTTL，TX/RX交叉并共地；Nano独立供电；Onboard模式、115200；当前线上帧为MAVLink 1 |
| ELRS ↔ PX4 | UART6 / `RC` | 接收机 TX→RX6，RX→TX6；供电按接收机铭牌；CRSF/ELRS |

45A 手册给出了 UART1=`TELEM1`、UART4=`TELEM2`、UART6=`RC` 的映射；当前实物为MTF占UART4/TELEM2、Nano使用空闲UART1/TELEM1、ELRS占UART6/RC。MTF官方给出5V供电、3.3V LVTTL、115200和50Hz。
## 当前执行顺序

1. 保存当前PX4 1.16.2参数、接线图和Nano到电机`FULL_PASS`报告作为实机基线。
2. 用录制样帧或人工输入开发`视觉算法→速度/位置目标`，加入时间戳、限幅、输入超时和退出归零。
3. 使用`脚本/SITL仿真`先验证Offboard控制器、动态控制分配和命令失联退出，不连接真实动力。
4. 按[[08-AirSim硬件在环与定位方案]]恢复AirSim/PX4 SITL，评估任务定位方案和视觉控制效果。
5. 机架完成后再做安装方向、振动、光流/测距精度、PID、失联策略和飞行测试。

当前向硬件在环阶段推进所需输入和操作清单见[[08-AirSim硬件在环与定位方案#开始下一阶段需要提供或确认的事项]]。

早期分段证据见[[测试记录/2026-09-23至29-系统联调总记录]]，最新端到端结果见[[测试记录/2026-10-03-Nano至电机端到端通过]]。

## Obsidian 使用方式

- **Canvas**：从总览拖入每个阶段笔记，沿箭头按门禁执行；完成后在画布节点颜色/阶段笔记的 `status` 属性中标记。
- **Properties**：每份阶段笔记记录 `status`、`owner`、`date`、`firmware`。完成标准没证据时保持“待验证”。
- **双链/反向链接**：把每次 [[测试记录模板|测试记录]] 链到对应阶段，问题笔记再反链到器件和阶段，避免故障信息散落。
- **核心模板插件**：将 `控制链路测试/模板` 设为模板目录，用模板创建当天的测试记录；不依赖额外安装。
- **Excalidraw 插件**：用于画实物焊盘、排线方向和线色图；原理链路继续用 Canvas。每根线在图上标来源、去向、电压和实测值。
- **Calendar / Daily Notes**：每天笔记写当日阶段、通过项和未解决问题；链接到该阶段及当天测试记录。Cmdr 和 Operon 当前无需加入此流程。
