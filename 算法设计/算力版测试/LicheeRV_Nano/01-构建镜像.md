# LicheeRV Nano 镜像构建文档（自定义 GC4653 摄像头）

> 目标：从零编译出可烧录的 SD 卡镜像，并把默认 sensor 从 `ov_os04a10` 切换为 `GC4653`。
>
> 环境：Ubuntu 22.04（VMware 虚拟机）。
>
> 实测结论：按本文流程可成功编译并出图。

---

## 1. 环境要求

| 项目 | 要求 | 实测情况 |
|------|------|----------|
| 操作系统 | Linux（Ubuntu 22.04 推荐） | Ubuntu 22.04.5 LTS |
| 磁盘空间 | ≥ 40 GB（源码 + 工具链 + 编译产物） | 扩容到 150 GB |
| 内存 | ≥ 8 GB 推荐 | 5.7 GB（需降并发，见 6.2） |
| 网络 | 能访问 GitHub（下载约 1.3 GB 工具链） | 正常 |

> 磁盘不足会导致 clone 与编译中途报 `设备上没有空间`。

### 1.1 磁盘扩容（如空间不足）

宿主机（VMware）中先把虚拟磁盘扩大，然后在虚拟机内执行：

```bash
# 确认磁盘已识别到新容量
lsblk
sudo fdisk -l /dev/sda

# 扩展分区（/dev/sda3 为根分区、且为最后一个分区时可用）
sudo apt install -y cloud-guest-utils
sudo growpart /dev/sda 3

# 扩展文件系统（ext4）
sudo resize2fs /dev/sda3

# 验证
df -h /
```

> 该命令支持在线扩容，无需重启。

## 4. 修改 sensor 配置为 GC4653

### 4.1 背景

SDK 通过 Kconfig 选择 sensor。GC4653 驱动**已内置**于 SDK，无需移植：

```
middleware/v2/component/isp/sensor/sg200x/gcore_gc4653/
├── gc4653_sensor_ctl.c      # 寄存器初始化、I2C 读写
├── gc4653_cmos_ex.h         # 数据结构、模式枚举
└── gc4653_cmos_param.h      # 分辨率/时序/MIPI 属性
```

关键参数（已核对，与官方 datasheet 一致）：

| 参数 | 值 | 说明 |
|------|-----|------|
| I2C 地址 | `0x29`（7-bit） | 对应 datasheet 的 `0x52/0x53`（8-bit） |
| 分辨率 | `2560x1440 @30fps` | 1440p |
| 数据格式 | RAW10 | MIPI CSI |
| lane_id | `{4, 3, 2, -1, -1}` | SDK 针对本板的 MIPI 接收映射 |

### 4.2 修改板卡 defconfig（关键步骤）

编辑：

```
build/boards/sg200x/sg2002_licheervnano_sd/sg2002_licheervnano_sd_defconfig
```

**原始内容存在 BUG**（写成了 `cv181x`，对本板 `sg200x` 无效）：

```diff
- CONFIG_SENSOR_TUNING_PARAM_cv181x_src_gcore_gc4653=y
- # CONFIG_SENSOR_TUNING_PARAM_sg200x_src_ov_os04a10=y
+ CONFIG_SENSOR_TUNING_PARAM_sg200x_src_gcore_gc4653=y
+ # CONFIG_SENSOR_TUNING_PARAM_sg200x_src_ov_os04a10 is not set
```

> 核心：把 `cv181x` 改成 `sg200x`。若不改，配置会被忽略，sensor 回退到默认的 `ov_os04a10`。

可用 sed 一键替换：

```bash
sed -i 's/CONFIG_SENSOR_TUNING_PARAM_cv181x_src_gcore_gc4653=y/CONFIG_SENSOR_TUNING_PARAM_sg200x_src_gcore_gc4653=y/' \
  build/boards/sg200x/sg2002_licheervnano_sd/sg2002_licheervnano_sd_defconfig
```

### 4.3 验证配置生效

```bash
source build/cvisetup.sh
defconfig sg2002_licheervnano_sd
grep "SENSOR_TUNING_PARAM=" build/.config
```

**期望输出：**

```
CONFIG_SENSOR_TUNING_PARAM="gcore_gc4653"
```

环境变量打印中应出现：

```
Sensor tuning bin: gcore_gc4653
```

## 5. 编译

### 5.1 标准流程

```bash
cd ~/Desktop/study/RMDrone/sources/LicheeRV-Nano-Build
source build/cvisetup.sh
defconfig sg2002_licheervnano_sd
build_all
```

> `source` 与 `defconfig` 定义的是 **shell 函数**，不跨终端保留，每开新终端都要重新执行。

### 5.2 后台编译（推荐，避免终端断开中断）

```bash
nohup bash -c 'unset LD_LIBRARY_PATH; export BR2_JLEVEL=4; \
  source build/cvisetup.sh && defconfig sg2002_licheervnano_sd && build_all' \
  > build.log 2>&1 &
```

**注意：**

- `build_all` 是 shell 函数，**不能用 `nohup build_all`**（会报 `没有那个文件或目录`），必须用 `bash -c` 包裹。
- `unset LD_LIBRARY_PATH` 用于规避 buildroot 报错（见 6.1）。
- `BR2_JLEVEL=4` 用于限制并发、避免 OOM（见 6.2）。

### 5.3 监控进度

```bash
# 看日志尾部
tail -30 build.log

# 确认进程存在
ps aux | grep build_all | grep -v grep

# 确认日志在增长（两次大小不同 = 在编译）
ls -l build.log; sleep 20; ls -l build.log
```

### 5.4 编译顺序（build_all 内部）

```
uboot → kernel → ramboot → osdrv → 3rdparty → middleware
      → buildroot(rootfs、Qt5) → 打包 → 生成 .img
```

耗时约 **1~4 小时**（取决于 CPU / 内存）。

## 6. 常见问题与解决

### 6.1 buildroot 报 `LD_LIBRARY_PATH` 错误

**现象：**

```
You seem to have the current working directory in your
LD_LIBRARY_PATH environment variable. This doesn't work.
make[2]: *** [support/dependencies/dependencies.mk:27：dependencies] 错误 1
```

**原因：** `LD_LIBRARY_PATH` 结尾（或中间）多了冒号，形成空路径项，等价于「当前目录 `.`」。buildroot 出于安全考虑拒绝编译。

典型诱因是 `.bashrc` / `.profile` 中这样写（`$LD_LIBRARY_PATH` 初始为空时会残留冒号）：

```bash
export LD_LIBRARY_PATH=/opt/MVS/lib/64:/opt/MVS/lib/32:$LD_LIBRARY_PATH
```

**解决（临时）：**

```bash
unset LD_LIBRARY_PATH
```

**解决（永久）：** 把 `.bashrc` / `.profile` 中的追加式写法改为固定值去重：

```bash
export LD_LIBRARY_PATH=/usr/local/lib:/opt/MVS/lib/64:/opt/MVS/lib/32
```

验证：`echo "$LD_LIBRARY_PATH"` **结尾不应有冒号**。

### 6.2 编译时 `cc1plus` 被 Killed（内存不足）

**现象：**

```
riscv64-unknown-linux-musl-g++: fatal error: Killed signal terminated program cc1plus
compilation terminated.
```

**原因：** 内核 OOM killer 杀掉了编译器进程。`-j32` 并行 + 内存偏小（如 5.7 GB）会瞬间打爆内存。

**解决：**

```bash
# ① 增加 swap 兜底（可热加载，不影响正在运行的编译）
sudo fallocate -l 8G /swapfile2
sudo chmod 600 /swapfile2
sudo mkswap /swapfile2
sudo swapon /swapfile2
free -h

# ② 降低并发重编（BR2_JLEVEL 可压制 buildroot 的 -j32）
export BR2_JLEVEL=4
```

> 最彻底的办法是给虚拟机分配 ≥ 12~16 GB 内存。

### 6.3 `qt5base` 首次编译失败

**现象：** 在 buildroot 阶段失败，错误 2；日志中 Qt **configure 成功**，但随后 `_all` 失败。

**原因：** qt5base 构建目录存在上次残留，重配置后状态不一致。

**解决：**

```bash
rm -rf buildroot/output/build/qt5base-*
# 重新执行 build_all（纯增量，前面已编内容不会重编）
```

> README 亦提示：`qt5svg` / `qt5base` 首次可能失败，**重跑一次**即可。
>
> 注：configure 阶段大量 `test config.xxx FAILED` 属**正常探测失败**（如 drm、xlib、odbc、win32 条件），不影响编译。

### 6.4 磁盘写满

**现象：** clone 或编译中途报 `设备上没有空间` / `No space left on device`。

**排查：**

```bash
df -h /
sudo du -xh --max-depth=1 / 2>/dev/null | sort -rh | head -20
```

**常见可清理项：**

| 目标 | 命令 |
|------|------|
| 回收站 | `rm -rf ~/.local/share/Trash/*` |
| VSCode 索引缓存 | `rm -rf ~/.cache/vscode-cpptools` |
| VMware 拖拽残留 | `rm -rf ~/.cache/vmware/drag_and_drop` |
| pip 缓存 | `rm -rf ~/.cache/pip` |
| 系统日志 | `sudo journalctl --vacuum-size=100M` |
| apt 缓存 | `sudo apt clean` |

### 6.5 重复启动多个 `build_all`

多个编译进程同时写入同一构建目录会导致互相破坏、随机报错、内存打爆。

```bash
# 检查
ps aux | grep build_all | grep -v grep

# 全部杀掉后只启动一个
pkill -9 -f "build_all"
pkill -9 -f "cc1plus"
```

### 6.6 停止/中断编译的正确做法

- ✅ 关闭终端**不影响**编译（`nohup` + `&` 已脱离终端）
- ✅ 不要在编译期间执行 `pkill -9 -f build_all`（会中断编译，日志会无错误地停在半截）
- ⚠️ 不要让虚拟机挂起/休眠
- ⚠️ 不要重复执行启动命令

```
.../rootfs/mnt/system/usr/lib/libsns_gc4653.so
.../rootfs/mnt/cfg/param/sipeed_gc4653_30fps_202403261356.bin
```

## 8. 烧录 SD 卡

### 8.1 把镜像拷到宿主机

从虚拟机把 `.img` 拖拽到 Windows，或使用共享文件夹 / `scp`。

### 8.2 Windows 烧录：Win32DiskImager

1. 下载：<https://sourceforge.net/projects/win32diskimager/>
2. **右键 → 以管理员身份运行**
3. **Image File**：选择 `.img`（路径避免中文/空格）
4. **Device**：选择 SD 卡盘符（如 `F:\`）
5. **Write** → 确认 → 等待 `Write Successful`

> 注意工具怪癖：**必须先选 Image File，Device 下拉才能正常选中**。

### 8.3 备选工具

- **Rufus**：<https://rufus.ie/>，以管理员运行；弹窗选 **DD 模式**
- **balenaEtcher**：<https://etcher.balena.io/>（对无分区裸盘可能误报「被锁定」）

### 8.4 烧录前的清理（如遇「被锁定」/ 分区异常）

```cmd
diskpart
list disk
select disk 2      :: ⚠️ 必须是容量匹配 SD 卡的那个编号
clean
exit
```

> 执行 `clean` 前**务必核对磁盘容量**，选错会清空整个硬盘。

### 8.5 Linux 下直接烧录（备选）

```bash
# 确认 SD 卡设备名（⚠️ 切勿写成 /dev/sda 系统盘）
lsblk

# 写入
sudo umount /dev/sdX* 2>/dev/null
sudo dd if=install/soc_sg2002_licheervnano_sd/images/xxx.img of=/dev/sdX \
        bs=4M status=progress conv=fsync
sync
```

### 8.6 启动验证

1. SD 卡插入 LicheeRV Nano
2. USB-C 供电
3. 见 [02-GC4653摄像头测试.md](02-GC4653摄像头测试.md) 完成登录与出图验证
